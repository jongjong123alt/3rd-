## 발표 전 직접 점검

- [ ] 배포 완료 후 실제 URL에서 첫 화면·로그인·과제 등록·조회 확인.
- [ ] 발표 5~10분 전에 접속해 무료 호스팅의 절전 상태 해제. 다시 시연 경로 확인.
- [ ] 교내 네트워크에서 실제 배포 URL과 Gemini 분석·저장까지 확인.
- [ ] Gemini API 계정의 현재 모델별 할당량·사용량 확인. 반복 분석으로 쿼터를 낭비하지 않기.
- [ ] 발표 PC·브라우저에서 기존 계정 로그인 및 정상 동작 확인. `.env`와 관리자 콘솔은 화면 공유하지 않기.
- [ ] 발표용 데이터와 계정 준비. 실제 개인정보를 공지·첨부파일에 넣지 않기.
- [ ] AI 호출 실패 대비 수동 과제 등록 흐름과 실제 촬영한 성공 화면 준비. 녹화·이미지는 사전 기록임을 명시.
- [ ] 학생 본인이 테스트를 직접 실행하고 수정 이유·결과를 검증 기록에 작성.
- [ ] 실제 배포 URL을 아래 제출 문안에 넣고 마감 전에 직접 전송.

## 배포 전에 결정할 사항

저장소에 Gunicorn·Render Blueprint·영구 저장 경로·서버 계정 생성 명령을 추가했다. 실제 서비스는 아직 생성하지 않았다. [아키텍처 문서](ARCHITECTURE.md)를 기준으로 플랫폼을 선택한 뒤 아래를 해결한다.

- 제공된 Gunicorn 설정으로 운영 서버 실행. debug는 비활성화.
- `GEMINI_API_KEY`, 고정된 `FLASK_SECRET_KEY`를 플랫폼 비밀 환경변수로 설정.
- SQLite와 첨부파일이 재배포·재시작 후 보존되는 영구 저장소 사용.
- 무료 플랜에서도 로그인 화면의 새 계정 만들기로 발표 계정 생성 가능. 운영 공개 가입은 기존 미소유 과제를 자동 귀속하지 않음. 영구 저장소 없는 환경에서는 계정·과제 유실 가능.
- HTTPS, 로그인, 계정별 접근 제어, CSRF, 업로드·백업 및 실제 Gemini 호출 점검.
