## 필수 준비
1. 서버를 종료합니다.
2. **기존 `instance/assignments.db`와 `instance/uploads` 폴더를 백업합니다.**
3. `git pull origin main`
4. `python -m pip install -r requirements.txt`
5. `.env`에 `FLASK_SECRET_KEY`를 충분히 길고 무작위인 값으로 설정합니다. 키를 저장소에 올리지 않습니다.
6. `python -m unittest discover -s tests -v`
7. `python app.py` 실행 후 브라우저에서 새로고침합니다.
8. **첫 계정은 반드시 기존 데이터 소유자가 PC에서 직접 만듭니다.** 기존 계정 없는 DB의 소유자 미지정 과제는 첫 계정에 귀속됩니다. 이전에 생성한 체크리스트·메모도 과제 소유권을 따릅니다.

## 직접 확인할 내용
- 로그인 전에는 대시보드 접근 불가, 로그아웃 시 접근 불가.
- 서로 다른 계정의 과제 상세 URL·파일·백업은 서로 보이지 않아야 함.
- 오늘/3일 내 마감 알림과 체크리스트, 일정 충돌 페이지 확인.
- Gemini 일정 생성 후 수정·삭제; API 키 없거나 서버 오류 시 오류 메시지 확인.
- JSON 백업 → 복원 후 기존 과제 유지, 새 과제 추가. 잘못된 JSON은 복원 거부.
- PDF 첨부 다운로드/삭제 및 과제 삭제 후 파일 삭제 확인.

## 보안 및 운영 주의
- 인증과 소유권 검사 등 기본 보호 기능을 구현했지만, **실서비스 공개 배포 수준의 보안 검증은 완료되지 않았습니다.** HTTPS, 비밀번호 재설정, 계정 생성 정책, 로그인 시도 제한의 영속화, 파일 악성코드 검사, 데이터 삭제/보존 정책 등 추가 작업이 필요합니다.
- 첫 회원가입은 localhost에서만 가능합니다. 외부에 공개하기 전에 로컬에서 계정/기존 데이터 귀속을 확인하세요.
- `FLASK_SECRET_KEY`가 바뀌면 로그인 세션이 무효화됩니다.
- 백업 JSON에는 과제·체크리스트·메모·AI 일정이 포함됩니다. **첨부파일 원본은 포함되지 않습니다.** 계정 비밀번호·API 키도 포함되지 않습니다.
- AI 일정은 실제 Gemini API 호출이 필요하며 단위 테스트에서는 API를 모의 처리합니다.
