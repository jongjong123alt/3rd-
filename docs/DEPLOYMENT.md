# Render 배포 안내

2026-11-24: 저장소 배포 설정 준비 완료. **실제 서비스 생성·배포는 아직 수행하지 않았다.**

## Render에 연결

1. Render에 GitHub 계정으로 로그인하고 **New → Blueprint**를 선택한다.
2. `jongjong123alt/3rd-` 저장소의 `main` 브랜치를 연결한다.
3. `render.yaml`을 읽은 설정에서 서비스와 디스크의 현재 요금을 확인한다. 이 구성은 **유료 Starter 웹 서비스 + 1GB 영구 디스크**다. 자동 생성 전에 비용을 검토한다.
4. `GEMINI_API_KEY`에 실제 키를 등록한다. 키를 GitHub·채팅·스크린샷에 넣지 않는다.
5. 서비스 생성 후 빌드·실행 로그와 실제 발급된 HTTPS URL의 `/health`를 확인한다.

Blueprint 대신 수동 Web Service를 만들면 다음 값을 사용한다.

| 항목 | 값 |
|---|---|
| 설치 명령 | `pip install -r requirements.txt` |
| 시작 명령 | `gunicorn -c gunicorn.conf.py app:app` |
| 상태 확인 경로 | `/health` |
| 영구 디스크 마운트 | `/var/data` |
| `APP_ENV` | `production` |
| `APP_DATA_DIR` | `/var/data` |
| `FLASK_SECRET_KEY` | 고정된 긴 무작위 문자열, Blueprint는 자동 생성 |
| `GEMINI_API_KEY` | 본인 Gemini 키 |
| `GEMINI_MODEL` | `gemini-2.5-flash` |

`FLASK_DEBUG`는 설정하지 않는다. 운영 모드는 시크릿이 없으면 시작을 거부하며 HTTPS용 Secure 세션 쿠키를 사용한다. 시크릿 변경 시 기존 로그인 세션은 무효화된다.

## 발표용 계정 생성

무료 플랜에서도 배포 사이트의 **로그인 → 새 계정 만들기**로 가입할 수 있다. 가입 후 자동 로그인되며 새 계정에는 본인이 등록한 과제만 표시된다.

Shell이 있는 환경에서는 선택적으로 다음 명령을 사용할 수 있다.

```bash
flask --app app create-user --username demo
```

비밀번호는 화면의 숨김 입력과 확인 입력으로 전달한다. 명령줄에 비밀번호를 적지 않는다. 아이디 3~32자(소문자·숫자·밑줄), 비밀번호 10~128자다. 기존 아이디를 덮어쓰거나 비밀번호를 변경하지 않는다.

운영 모드의 웹 회원가입은 소유자 없는 기존 과제를 자동 귀속하지 않는다. CLI로 첫 계정을 만들 때 기존 과제가 있으면 귀속 여부를 확인하므로 실제 소유자만 진행한다. 무료 플랜의 임시 SQLite에서는 계정도 재시작·재배포 후 사라질 수 있다. 공개 회원가입 추가가 데이터 영구 보존을 해결하는 것은 아니다.

## 데이터 보존과 이전

`APP_DATA_DIR` 아래 `assignments.db`와 `uploads/`를 함께 저장한다. 로컬 기본값은 기존 `instance/`이므로 기존 데이터 위치를 바꾸지 않는다. 환경변수만 바꿔도 기존 파일이 자동 이전되는 것은 아니다.

발표 데이터는 로컬 앱의 계정별 ZIP 백업을 만든 뒤 배포 앱에서 로그인하여 추가 복원하는 방법을 권장한다. 같은 ZIP 반복 복원 시 중복될 수 있다. 배포 후 과제와 첨부파일을 등록하고 재시작한 뒤 둘 다 유지되는지 확인한다. 영구 디스크와 별개로 백업을 보관한다.

무료의 임시 파일 저장 환경에서 SQLite 데이터를 유지한다고 보장할 수 없다. 무료 배포가 필수라면 외부 DB·파일 저장소로 전환하는 추가 작업이 필요하다. Railway 등에서도 같은 실행 설정을 사용할 수 있지만 영구 볼륨을 별도로 연결하고 `APP_DATA_DIR`을 실제 마운트 경로로 지정해야 한다.

## 운영 범위와 확인

Gunicorn 1개 프로세스·4개 스레드를 사용한다. 기존 메모리 로그인 시도 제한을 프로세스 사이에 분산하지 않기 위한 구성으로, 여러 인스턴스 확장을 지원하는 설계는 아니다. AI 호출은 동기식이며 Gunicorn 제한은 180초다. 외부 API 전체 시간이나 무료 쿼터를 보장하지 않는다.

실제 배포 후 로그인 → 공지 분석 → 수정·저장 → 달력·체크리스트 → 첨부파일 → 재시작 후 유지까지 확인한다. `/health`는 기본 응답 점검이며 Gemini·DB 전체의 정상 동작을 증명하지 않는다. 마지막으로 교내 네트워크와 발표 PC에서 [발표 체크리스트](DEMO_DAY_CHECKLIST.md)를 수행한다.
